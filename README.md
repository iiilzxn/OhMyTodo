# 待办 · OhMyTodo

面向 Windows 日常工作的个人待办应用。桌面上保留一个安静的小悬浮窗，需要时展开完整任务和发版计划。数据保存在本机；不连接 Git 仓库或代码托管平台。

## 启动

构建后的应用放在 `output/app/`：

- `OhMyTodo.exe`：直接运行。
- `OhMyTodo_0.2.2_x64-setup.exe`：当前用户安装包，适合长期使用和 Windows 系统通知。

首次打开是空任务库，可以直接添加待办，也可以点“体验示例”查看一组可编辑、可删除的示例。关闭主窗口会收进系统托盘；从托盘菜单或“设置 → 退出应用”完全退出。

0.2.1 修复：主窗口和悬浮窗均已禁用 WebView2 默认网页右键菜单（返回、刷新、另存为、打印等）。文本编辑仍可使用 Ctrl+C / Ctrl+V / Ctrl+X / Ctrl+A / Ctrl+Z 等快捷键。

0.2.2 更新：年月选择改为网格面板，支持键盘选择和直接输入年份。悬浮窗右上角的日历图标打开独立浮层，点外侧、关闭按钮或按 Esc 收起，原来的待办 / 发版页面和输入草稿会保留。

## 日常使用

- **今天**：主动加入今天的任务，以及已到期、逾期的任务。
- **收集箱**：尚未安排日期、也未加入今天的想法。
- **计划**：按日期查看有安排的任务。
- **工作 / 生活**：简单分类。
- **已完成**：保留完成记录，可以重新打开。
- **搜索**：搜索任务标题、备注、子任务、项目、版本和 Feature 功能项。

输入一句话后按 Enter 即可添加。点击任务打开详情，可补充日期、提醒时间、备注、子任务、重要标记和每日 / 每周重复。完成重复任务后会安排下一次；撤销完成时，尚未编辑或完成的自动生成任务也会撤销。

删除待办、删除发布计划后会短暂显示“撤销”。删除 Feature 后撤销会恢复内容，需要重新确认验收。

## 桌面悬浮

工具栏“悬浮窗”打开独立小窗口，支持拖动、缩放、置顶开关和折叠。它与主窗口共用数据，修改后立即同步。

- **今天**：快速添加、完成任务；点击任务在主窗口查看详情。
- **发版**：选择版本，展开 Feature、勾选功能项、确认验收，也可直接勾选发布步骤。
- **右上角日历按钮**：临时展开日历浮层，不占用页签；支持假期查看、日期范围选择与标记。折叠状态下点击也可直接展开日历。

快捷键：

| 按键               | 功能               |
| ------------------ | ------------------ |
| Ctrl + Alt + N     | 全局快速添加待办   |
| Ctrl + Alt + Space | 显示 / 隐藏悬浮窗  |
| Ctrl + K           | 应用内搜索         |
| Ctrl + N           | 应用内新建待办     |
| Esc                | 关闭当前编辑对话框 |

若全局快捷键被其他软件占用，设置页面会显示提示；工具栏和托盘入口仍可使用。

## 独立规划日历（0.2 新增）

主窗口侧栏和悬浮窗均有“日历”入口。日历有自己的日期标记，不会读取、创建、完成或关联待办与发布计划。

- **月历 / 年览 / 标记清单**：点击年月打开网格选择面板；年份可分组翻页或直接输入 1900—2100 年，月份一屏显示。支持回到今天、查看整年、搜索全部标记。
- **单日标记**：点击日期后选择“标记这一天”，或直接双击日期。
- **范围标记**：按住鼠标左键拖动选择连续日期；先点击起点、切换月份，再按 Shift 点击终点即可跨月。也可在编辑窗口直接输入起止日期。
- **颜色与备注**：六种颜色，支持名称、备注、修改和删除撤销；重叠标记分行展示，空间不足时显示“+N 更多”，点击日期可查看全部。
- **键盘操作**：方向键移动日期，Shift + 方向键扩选，Enter 标记当前选择；在主窗口日历中 Ctrl + N / N 新建标记，Ctrl + K 搜索日历标记。
- **农历和节气**：农历日期、常见节日和二十四节气在本地计算。
- **独立导出**：“导出标记”生成全日事件 `.ics` 文件，只包含手动日历标记；不会包含待办、发布计划或自动导出官方假期。无需登录任何日历服务。

范围首尾日期都包含在标记内。工作日统计以中国大陆已收录的官方放假、调休和普通周末为基础；未收录年份会明确显示“估算”。支持 1900—2100 年，单条标记最长 3660 天。

**节假日数据**：当前离线内置 2025、2026 年中国大陆全体公民的官方安排。“休”代表官方放假/调休日，“班”代表周末调休补班。当天详情会区分法定节假日与调休日，普通周末不冒充法定假期。其他年份可以正常规划和标记，但会提示官方安排未收录，不生成猜测的调休标签。

数据来源（核对日期：2026-09-27）：

- [国务院办公厅关于 2025 年部分节假日安排的通知](https://www.gov.cn/zhengce/zhengceku/202411/content_6986383.htm)
- [国务院办公厅关于 2026 年部分节假日安排的通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)
- [全国年节及纪念日放假办法（2024 年修订，2025 年起施行）](https://www.gov.cn/zhengce/content/202411/content_6986380.htm)

农历计算使用 [lunar-typescript](https://github.com/6tail/lunar-typescript)；授权信息见 `THIRD_PARTY_NOTICES.md`。官方假期与调休数据单独维护在 `src/calendar/holidays.ts`，未使用农历库的假期推测表。

**升级兼容**：0.2 首次启动会在 `backups/` 中保存 `before-calendar-upgrade-*.json`，再升级数据格式。原有待办和发布计划保留；新版数据请使用 0.2 或更新版本打开。0.1 备份可以导入，预览会显示其中日历标记为 0；恢复仍会先备份当前数据。

## 发布计划

新建待办时可选择 **普通待办、Feature、Release**。

1. 创建 Release，填写项目、版本和发布日期。
2. 添加本次 Feature，每个 Feature 可以拆成多条功能 / 验收项。
3. 从流程模板复制一份独立的发布清单；步骤可编辑、增删、排序，也可取消“必做”。
4. 功能子项全部完成后，单独点击“确认验收”。修改功能内容会取消之前的验收状态。
5. 所有 Feature 已验收、所有必做流程完成后，才能点击“完成发版”。

已发布版本会记录完成时间并锁定编辑，可以通过“重新打开计划”继续修改。模板在“设置”中维护；修改模板不会改变已经建立的版本计划。

版本名称是本地计划字段，不要求对应任何真实 Git Tag。应用不读取仓库、PR、提交或 CI 状态，也不执行发布命令。

## 数据、备份和提醒

默认数据目录为 `%LOCALAPPDATA%\com.ohmytodo.desktop\`，准确路径可在“设置 → 本地数据”查看和打开。

- 数据库：`ohmytodo.sqlite3`，采用 SQLite 事务、WAL 和完整同步写入。
- 自动备份：`backups/daily-YYYY-MM-DD.json`，每天首次启动 / 修改前保存一份，保留最近 14 个备份日期。
- 手动备份：从设置导出 JSON；恢复前会验证格式和业务规则，并额外备份当前数据。
- 主题和通知偏好包含在备份中；Windows 开机启动设置由系统单独管理。
- 日历标记包含在完整应用备份中，也可以单独导出为 `.ics`。

数据库正在使用时，请优先使用“导出备份”，不要只复制一个正在写入的 SQLite 主文件。

提醒由桌面进程每 30 秒检查一次。带提醒时间的未完成任务到时发送通知；启用发版提醒的版本在前一天及当天 09:00 提醒。应用须在运行（可以留在托盘），完全退出或电脑关机期间无法通知；重新运行后会补发最近 24 小时内尚未发送的提醒。Windows 通知设置和勿扰模式会影响弹出展示。发布安装版后，系统通知拥有正确的应用身份。

## 开发

技术栈：Tauri 2、React、TypeScript、Vite、Rust、SQLite（rusqlite）。使用本机 WebView2 渲染，所有任务操作由 Rust 数据层验证并事务保存。多窗口通过带版本号的事件同步，较旧事件不会覆盖新状态。

已核对的本机工具链：Node.js 22.18.0、pnpm 10.15.0、Rust 1.98.1 / MSVC、Visual Studio 2022 C++ 工具、Windows SDK 10.0.22621.0、WebView2。具体依赖由 `pnpm-lock.yaml` 和 `src-tauri/Cargo.lock` 锁定。

```powershell
pnpm install --frozen-lockfile
pnpm desktop
```

`pnpm dev` 只运行前端开发服务器；完整应用需要用 `pnpm desktop` 启动，以提供本地数据和桌面接口。

构建安装包：

```powershell
pnpm package
```

输出为 `src-tauri/target/release/ohmytodo.exe` 和 `src-tauri/target/release/bundle/nsis/` 下的安装包。

执行 `powershell -NoProfile -File scripts/package.ps1` 可构建并整理成品到 `output/app/`，同时生成 SHA-256 校验清单。已有构建结果时可加 `-SkipBuild`。

## 验证

```powershell
pnpm test
cargo test --manifest-path src-tauri/Cargo.toml --lib
pnpm tauri build --debug --no-bundle
pnpm test:ui
```

UI 测试运行真正的 Windows Tauri / WebView2 应用，通过仅在测试进程启用的本地调试端口执行操作。测试数据位于 `output/verification/data-时间戳/`，与正式数据分开。验证截图和结果保存在 `output/verification/`。

测试覆盖日期边界、重复任务及撤销、功能验收与发版限制、SQLite 重启保存、备份恢复、悬浮窗口同步、置顶和折叠。正式应用不会主动启用调试端口。
